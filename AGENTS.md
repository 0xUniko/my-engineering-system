# AGENTS.md

- Represent semantically distinct runtime cases with distinct types and explicit, exhaustive case analysis. Keep case-specific flows separate while their invariants, effects, or resource handling differ; merge only into a genuinely identical continuation. Do not box branches into an optional, variant, or wrapper merely to unpack or re-dispatch them downstream.
- Introduce a new state or wrapper only when existing values cannot express a required invariant, ownership, or lifetime. Create it no earlier than its first necessary use; otherwise pass values directly from their existing owner. A resource's lifetime alone does not justify an additional surrounding abstraction.
- Use the narrowest types that express the valid values and required capabilities. Use concrete types for single cases, closed algebraic data types for finite alternatives, and statically constrained generics (interfaces, traits, type classes, or concepts) for behavior genuinely shared across types. Leave type parameters unconstrained only when no type-specific capabilities are required. Avoid inheritance and runtime dispatch.
- Avoid explicit loops unless explicitly allowed; use idiomatic functional combinators such as `map`, `filter`, `fold`, and language-specific equivalents.
- Except where required by third-party APIs, mutable state may exist only as state threaded through `fold`; use `fold` only where that state is produced or carried, and traverse an existing owner for side effects with `for_each` (`try_for_each` when fallible).
- Name values by their semantic role and type, not their representation or origin. Use singular names for elements and plural names for collections. Across bindings and function boundaries, keep the same name stem when both the type (ignoring borrow/ownership form) and the semantic role remain unchanged, and use a distinct name when either changes. The method receiver keeps the name `self`.
- Validate each invariant once at its owning boundary; trust established invariants and dependency contracts. Avoid redundant checks, speculative fallbacks, and defensive scans or copies.
